# 万星日推 · GitHub 开源项目发现站

一个纯静态的单页网站：每天推荐 10 个 Star 过万的 GitHub 项目，支持全站千星项目搜索、新锐创新项目雷达、收藏分组。

**线上地址：<https://vv545A.github.io/github-star-daily/>**
**仓库地址：<https://github.com/vv545A/github-star-daily>**

**双击 `index.html` 也能用**，不需要装环境、不需要起服务，离线也能浏览和搜索。

## 二、页面结构

- **每日推荐**：日期做种子，同一天固定同一批，跨天自动换；「换一批」可手动换。每批保证覆盖 5 个以上方向、同一方向最多 2 个。
- **创新雷达**：按方向筛选新锐项目，按星速（Star ÷ 上线月数）排序，越靠前说明越被需要。
- **收藏**：点卡片右上角星标收藏，按技术方向自动分组，数据存在浏览器 localStorage（键名 `ghstar_favorites_v1`）。

## 三、卡片上的每块信息

| 位置 | 内容 |
|---|---|
| 标题 | `作者 / 项目名`，名字可点进 GitHub |
| 元信息 | Star 数、Fork 数、主语言（带官方色点）、`⚡新锐` 标记、`自动概述` 标记 |
| 中文说明 | 是什么 / 什么时候用 / 怎么上手 三段 |
| 标签 | 方向标签（彩色）+ 最多 3 个技术标签，点任意标签直接搜索 |
| 安装 | `git clone` 命令（可一键复制）、Release 包下载、源码 ZIP 下载 |
| 底部 | GitHub 仓库直达链接、最近更新时间 |

## 四、数据是怎么来的

```
repos.jsonl            抓取原始快照（GitHub Search API）
   │
   ├── anno1~5.py       人工中文标注（335 条，方向/标签/简介/场景/上手提示）
   ├── topics.py        454 条 topic → 中文词典（给长尾项目自动生成说明、让中文搜索能命中）
   └── build.py         合并 → assets/data.js + assets/data-extra.js
```

- **分两个数据文件**：`data.js`（万星全量，首屏加载）+ `data-extra.js`（5000–9999 星，首屏后懒加载），避免打开就卡。
- **长尾项目的中文说明是规则生成的**（卡片上有 `自动概述` 标记），不是人工翻译；同时保留英文原描述供对照。人工精选的 335 个项目没有任何自动文案。
- **已排除** 77 个不适合收录的仓库：归档项目、激活工具、翻墙代理客户端、Deepfake 换脸、DDoS/攻击工具、盗版教材、政治议题与生活类非技术内容。

## 五、自动更新（已开启，无需手动）

仓库里有一条 GitHub Actions 工作流 `.github/workflows/update-data.yml`，**每天北京时间凌晨 3:30** 自动执行：

```
抓取最新快照（Star≥10000 + 5000~9999，约 1.2 万条）
   → 重建 assets/data.js / data-extra.js
   → 跑自检（不通过就中止，不提交）
   → 提交并触发 Pages 重新部署
```

你也可以在仓库的 **Actions 页面 → 每日更新数据 → Run workflow** 手动点一次。

几个设计上的选择：

- **带了令牌抓取**：Actions 里用内置 `GITHUB_TOKEN`，搜索限额从 10 次/分钟提到 30 次/分钟，全程约 **12 分钟**（不认证要 25 分钟以上）。单次运行约 150 个请求。
- **抓完先自检**：万星池不足 4500 条、合计不足 10000 条、精选不足 300 条，任一条不满足就直接失败退出，**不会提交**——宁可这一天不更新，也不让半截数据覆盖掉线上能用的版本。
- **仓库体积恒定**：数据文件每天约 1.3MB，照常提交一年会涨到 450MB。所以工作流判断「上一条提交也是自动数据更新」时，会用 `git commit --amend` 覆盖掉它，仓库里始终只有**一个滚动更新的数据提交**，体积恒定在 1MB 左右。代价是数据更新没有历史记录。

想关掉自动更新：删掉 `.github/workflows/update-data.yml` 即可，网站照常运行，只是数据停留在最后一次。

## 六、本地手动更新（想自己跑时）

```bash
cd _build

# 1) 抓最新快照（全量重抓，受限流影响会慢）
set GITHUB_TOKEN=你的令牌     # 有令牌快 3 倍，没有也能跑
python fetch_all.py --tier 1   # Star≥10000（日推池）
python fetch_all.py --tier 2   # 5000–9999

# 2) 重新生成前端数据
python build.py

# 3) 自检（退出码非 0 表示有问题）
node test.js

# 4) 推到 GitHub（走 API，本机 git push 到 github.com 会被拦）
set GITHUB_TOKEN=你的令牌
python deploy.py --repo github-star-daily
```

> `deploy.py` 默认**不推** `data.js` / `data-extra.js` / `topics.js`——这三个文件归 GitHub Actions 每天维护，
> 手动推会用你本地旧快照覆盖掉 CI 刚抓的新数据。只有首次建站（仓库里还没有数据）时才需要加 `--with-data`。

`fetch_all.py` 的说明：
- GitHub 搜索接口未登录限 **10 次/分钟**，认证后 **30 次/分钟**；脚本靠环境变量 `GITHUB_TOKEN` 自动切换节奏（也可用 `GH_SLEEP` 手动指定间隔秒数）。
- 每个区间最多返回 1000 条，脚本会自动二分星区间直到能一次拿完，因此能突破 1000 条上限。
- 抓取过程中的分片缓存在 `_build/raw/`，进度在 `fetch_state.json`。**想强制全量重抓就删掉这两个**；中途断了直接重跑即可续传。

## 七、想填 GitHub Token（可选）

页面右上角齿轮可以填一个 Personal Access Token：
- 不填：每小时 60 次仓库查询、每分钟 10 次搜索，日常够用；
- 填了：额度大幅提高，同步和全站搜索都更顺畅。

Token 只存在你本机的 localStorage（键名 `ghstar_token_v1`），不会上传到任何地方，代码里也没有任何埋点。

## 九、已知边界

- **Star 数是快照**：页面底部会显示快照日期，点「同步最新 Star」才拉实时值。同一个项目 7 天内不会重复请求，避免浪费额度。
- **本地搜索不到 ≠ GitHub 没有**：本地库是 11,958 个高星项目，更长尾的项目点「在 GitHub 全站搜索」即可，那条路径是实时的。
- **自动概述不是翻译**：它是根据项目标签拼出来的客观描述（语言、方向、上线时间、Star 规模），准确性有保证但信息量不如人工简介；想看作者原话就看卡片里的英文原描述。
- **未收录归档项目**：已归档（不再维护）的仓库不进入推荐和本地库，例如 pocketbase 目前已归档。搜索这类项目请用「在 GitHub 全站搜索」。
